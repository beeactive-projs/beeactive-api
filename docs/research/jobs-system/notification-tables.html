Notification System — Proposed Tables

Four tables for the multi-channel notification module. Pattern adapted from clym/events-api with the alert/receipt split, plus a separate device-token table that handles web push + Ionic mobile FCM in one place.

Tables

notification
The message itself. One row per event, not per recipient. Broadcasts share one row.
ColumnTypePurpose
id PK CHAR(36) UUID, project convention
type VARCHAR(64) Enum: SESSION_REMINDER_1H, INVOICE_PAID, etc.
title VARCHAR(200) Short headline shown in the bell
body TEXT Full notification text
data JSONB { screen, entityId, action } for FE deep-linking
severity VARCHAR(16) info / success / warn / error — drives icon & color
icon_url NULL VARCHAR(300) Optional icon override (otherwise derived from severity)
priority SMALLINT Default 1. Higher = more prominent in the UI
audience_type VARCHAR(16) USER / GROUP / PLATFORM
audience_id NULL CHAR(36) user/group id; null when audience is PLATFORM
deliver_at NULL TIMESTAMPTZ When recipients start seeing it (null = immediate)
expire_at NULL TIMESTAMPTZ Auto-hides after this date
fingerprint NULL VARCHAR(64) sha256 of (type + dedup keys) — prevents duplicates
created_at TIMESTAMPTZ Standard
updated_at TIMESTAMPTZ Standard

(deliver_at) WHERE deliver_at IS NOT NULL (expire_at) WHERE expire_at IS NOT NULL (fingerprint) WHERE fingerprint IS NOT NULL (audience_type, audience_id)
notification_receipt
Per-recipient state: delivered, viewed, read, clicked, dismissed. One row per (notification, user).
ColumnTypePurpose
id PK CHAR(36) UUID
notification_id FK CHAR(36) → notification.id (CASCADE on delete)
user_id FK CHAR(36) → user.id — the recipient
delivered_at NULL TIMESTAMPTZ When in-app worker created the receipt (≈ "sent to bell")
viewed_at NULL TIMESTAMPTZ When user opened the bell dropdown and saw it
read_at NULL TIMESTAMPTZ When marked read (clicked or "mark all read")
clicked_at NULL TIMESTAMPTZ When user followed the deep link
dismissed_at NULL TIMESTAMPTZ When user X'd it without reading
delivered_channels JSONB Audit: { in_app: 'sent', email: 'sent', push: 'failed:no_devices' }
created_at TIMESTAMPTZ Standard
Indexes & Constraints
UNIQUE (notification_id, user_id) (user_id, read_at, created_at DESC) — bell badge query (user_id, viewed_at) — analytics (notification_id) — find all recipients of an alert
notification_preference
Per-user channel toggles. Sparse — only filled when user changes from default.
ColumnTypePurpose
id PK CHAR(36) UUID
user_id FK CHAR(36) → user.id
type VARCHAR(64) Notification type (e.g. SESSION_REMINDER_1H)
channels JSONB { in_app: true, email: true, push: false, sms: false }
updated_at TIMESTAMPTZ Audit
Indexes & Constraints
UNIQUE (user_id, type) (user_id) — settings page query
device_token
One row per device registered for push. Web Push + Ionic mobile FCM live here together.
ColumnTypePurpose
id PK CHAR(36) UUID
user_id FK CHAR(36) → user.id (owner)
platform VARCHAR(16) web / ios / android
token TEXT FCM token, or JSON-stringified Web Push subscription
endpoint_hash VARCHAR(64) SHA256 of unique endpoint — for the UNIQUE index
device_label NULL VARCHAR(120) Optional UA / device name for "logged-in devices" UI
last_seen_at TIMESTAMPTZ Updated on app open / browser visit. Used to prune stale devices
revoked_at NULL TIMESTAMPTZ Set on logout, permanent push failure, or user "remove device"
created_at TIMESTAMPTZ Standard
Indexes & Constraints
UNIQUE (user_id, endpoint_hash) (user_id, revoked_at) — push worker query (last_seen_at) — pruning sweeper

Relationships

user (1) ─────┬───── (N) notification_receipt ──── (N) notification │ (audience_type, audience_id) ├───── (N) notification_preference one alert → many receipts (broadcast) │ one user → many alerts via receipts └───── (N) device_token

Delivery flow when notify() fires

  1. notify(userId, SESSION_REMINDER_1H, ...) is called by a service or scheduler.
  2. Create the alert: insert one row into notification (the message).
  3. Resolve recipients: for USER audience that's just userId; for GROUP walk group_member; for PLATFORM all users.
  4. Create receipts: insert one row per recipient into notification_receipt with delivered_at = now().
  5. Read preferences: look up notification_preference per recipient (fall back to system default if no row).
  6. Fan out to channels: for each enabled channel, enqueue a job:
    • notifications.email_send → Resend
    • notifications.push_send → looks up device_token rows, sends via web-push lib (web) or FCM (ios/android)
    • notifications.sms_send → Twilio (later)
  7. Update audit: workers write to receipt.delivered_channels with 'sent', 'failed:reason', or 'skipped:preference_off'.

How states differentiate (the read/sent/clicked question)

State Columns set What it means
Created notification row exists, no receipt yet Producer enqueued it; in-app worker hasn't run
Sent / Delivered receipt.delivered_at In-app worker created the receipt → bell will show it
Channel status receipt.delivered_channels.email = 'sent' Per-channel result: sent / failed:reason / skipped:preference_off
Viewed receipt.viewed_at User opened the bell dropdown (FE marks viewed on dropdown open)
Read receipt.read_at User explicitly marked it read or clicked it
Clicked receipt.clicked_at User followed the deep link to the screen
Dismissed receipt.dismissed_at User X'd it without reading
Expired notification.expire_at < now() Auto-hidden by the bell query, can be cleaned up

The unread badge count = WHERE user_id = ? AND read_at IS NULL AND dismissed_at IS NULL AND (expire_at IS NULL OR expire_at > now()).
